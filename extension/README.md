# Commeet → POVIS 자동입력

Commeet에 로그인해 면담 기록을 불러오고, 그 회의에 참석한 학생 전원에 대해
POVIS **지도면담입력** 화면에서 학번 선택 → 지도면담 입력 → 네 항목 채우기 →
저장을 반복하는 확장입니다.

## 설치

**배포판 (권장)** — Chrome 웹 스토어에 올린 뒤 그 링크로 설치합니다. 스토어에
올리는 방법은 아래 "배포"를 보세요.

**개발/직접 설치** —
1. Chrome에서 `chrome://extensions` 열기
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → 이 `extension/` 폴더 선택
4. 툴바의 확장 아이콘 클릭 (⚙에서 서버 주소를 바꿀 수 있습니다 - 로컬 서버로
   개발할 때는 `http://localhost:8000`을 `host_permissions`에 넣어야 합니다)

권한은 POVIS(`povis.postech.ac.kr`)와 Commeet(`commeet.postech.ac.kr`,
구 주소 `commeet.knpu.re.kr`) 도메인, 그리고 스크린샷 저장용 `downloads`뿐입니다.

## 배포

Chrome은 웹 스토어 밖의 확장(`.crx`)을 일반 사용자에게 설치시켜 주지 않습니다
(기업 정책으로 강제 설치하는 경우만 예외). 그래서 선택지는 둘입니다:

1. **Chrome 웹 스토어 - "미등록(unlisted)" 공개** ← 교수 몇 분께 나눠 주는 용도에 맞음.
   검색에는 안 나오고 링크를 아는 사람만 설치합니다.
   - [Chrome 웹 스토어 개발자 대시보드](https://chrome.google.com/webstore/devconsole)에
     Google 계정으로 등록 (1회 등록비 $5)
   - `scripts/pack_extension.sh` 로 zip 생성 → 대시보드에서 "새 항목" → zip 업로드
   - 스토어 등록 정보(설명, 스크린샷 1280×800 1장 이상, 아이콘 128px), 개인정보
     처리 방침 URL, 권한 사용 이유("downloads: 입력 화면 스크린샷 저장",
     "scripting/host: POVIS·Commeet 페이지 조작")를 적고 검토 제출
   - 공개 범위를 **미등록**으로 두면 검토 통과 후 링크로만 설치 가능. 검토는
     보통 며칠 걸립니다. 버전을 올릴 때마다(`manifest.json`의 `version`) 다시
     업로드·검토합니다.
2. **압축해제 로드** — 위 "개발/직접 설치". 사용자가 폴더를 갖고 있어야 하고
   Chrome이 매번 "개발자 모드 확장" 경고를 띄우지만, 한두 명이면 이걸로 충분합니다.

## 쓰는 법

1. **로그인** — Commeet 계정으로 로그인합니다. 기본 서버는 ⚙ 버튼으로
   바꿀 수 있습니다(`https://commeet.postech.ac.kr` 또는 로컬 서버).
2. **내 일정** — 내가 만든 일정만 나옵니다(면담 기록은 주최자만 작성하므로).
   고른 뒤 **면담 기록 불러오기**.
3. **면담 기록** — 그 일정의 기록 목록. 작성 중인 초안은 `[작성 중]`으로 표시됩니다.
4. **POVIS 일괄 입력** — 기록을 고르면 참석 학생 목록과 각자의 처리 예정
   상태(입력 예정 / 학번 없음 / 내용 없음)가 보입니다. POVIS에서
   **학사 → 지도학생면담 → 지도면담입력** 화면을 열어 둔 뒤 **자동 입력**을
   누르면 학생마다 다음을 반복합니다:
   - 목록에서 학번 링크 클릭 → 면담내역이 로드되면 같은 날짜 면담이 이미
     있는지 확인 (있으면 건너뜀, "같은 날짜 면담이 있어도 입력"으로 강제 가능)
   - **지도면담 입력** → 면담일과 학업지도/생활지도/진로지도/기타사항을 UI5
     바인딩을 통해 쓰고 되읽어 검증 (빈 항목도 비워 씀 - 이전 학생 글이 남지 않도록)
   - 채운 화면을 **스크린샷**으로 저장: `회의_면담일_이름.png`. 폴더는
     다운로드 폴더 기준 하위 경로(비우면 다운로드 폴더 바로 아래). 확장은
     다운로드 폴더 밖에는 저장할 수 없습니다.
   - **저장** → 뜨는 확인/안내창은 긍정 버튼으로 넘기고, 면담내역이 늘거나
     입력 화면이 닫히면 성공으로 판정 → **이전**으로 목록 복귀
   - "채우기만 하고 저장하지 않기"를 켜면 저장 없이 채웠다 되돌아옵니다
     (처음 한 번은 이걸로 돌려 보는 것을 권합니다).

   작업은 팝업이 아니라 서비스 워커(`background.js`)에서 돌아가므로 팝업을
   닫아도 계속됩니다. 다시 열면 진행 상황과 학생별 결과(저장됨 / 건너뜀 /
   목록에 없음 / 실패 / 확인 필요)가 보이고, **중단**은 지금 학생을 끝낸 뒤 멈춥니다.
5. **선택한 학생만** — POVIS 입력 화면이 열려 있을 때 한 명 내용만 채우는
   수동 모드(저장은 직접). ⚙ 설정 안의 **필드 스캔**은 POVIS 화면 구조가 바뀌어
   입력이 실패할 때 필드 경로를 확인하는 진단 도구입니다.

비밀번호는 저장하지 않습니다. 로그인 요청에 한 번 실려 갈 뿐이고, 남는 것은
브라우저가 관리하는 Commeet 세션 쿠키뿐입니다.

## 기록에서 값을 꺼내는 규칙

틀리기 쉬운 곳이라 코드(`popup.js`의 `notesFor`)와 함께 적어 둡니다.

- `notesMode`가 `"individual"`이면 학생별 노트(`perStudentNotes`), 아니면
  공통 노트(`sharedNotes`)를 씁니다.
- `perStudentNotes`의 키는 **학번이 아니라 참석자 `key`**입니다. Commeet 화면
  코드가 이름으로도 폴백하므로(`record-form.js:710`) 여기서도 `key` → `name`
  순으로 찾습니다. 동명이인이 있으면 어긋날 수 있습니다.
- `present === false`(불참자)는 목록에서 제외합니다.
- `undecryptable`(복호화 실패) 기록은 배지로 표시합니다 - 내용이 비어 보이는
  것을 "빈 기록"으로 오해하지 않도록.
- 빈 항목은 채우지 않습니다. POVIS에 이미 있는 값을 빈 문자열로 덮지
  않기 위해서입니다.

## 왜 이렇게 만들었나 (POVIS 쪽)

POVIS는 SAPUI5(1.120.21) 앱입니다. 두 가지가 구현을 결정했습니다.

**1. 바인딩을 통해 써야 한다.** `field.value = ...` 후 `input`/`change`
이벤트를 흉내 내는 흔한 자동입력 방식은 여기서 **조용히 실패합니다**. 화면에는
새 값이 보이지만 UI5 모델은 옛 값 그대로입니다. 그렇다고
`model.setProperty()`로 끝나지도 않습니다 - 화면·모델에는 값이 있는데 저장하면
서버가 "면담결과를 입력하세요"라고 답합니다. POVIS 프레임워크(U4A)가 모델의
`propertyChange` 이벤트로 바뀐 필드를 추적해 서버에 보내는데, `setProperty`는
그 이벤트를 내지 않기 때문입니다. 실측 결과:

| 방법 | 화면 | UI5 모델 | 서버 저장 |
|---|---|---|---|
| DOM 직접 쓰기 + 이벤트 | 새 값 | **옛 값** | ✗ |
| `model.setProperty(path, v)` | 새 값 | 새 값 | **✗ "면담결과를 입력하세요"** |
| `control.getBinding("value").setValue(v)` + `model.checkUpdate(true)` | 새 값 | 새 값 | ✓ |

그래서 바인딩으로 쓰고, 채운 뒤 반드시 되읽어 일치를 확인합니다.

**2. 필드는 바인딩 경로로 찾아야 한다.** UI5가 붙이는 DOM id(`__area57-inner`)는
로드마다 바뀝니다. `/GS_GOAL/ZGOAL` 같은 바인딩 경로는 백엔드 필드명이라
안정적입니다.

콘텐츠 스크립트의 격리된 world에서는 `window.sap`이 보이지 않으므로
`chrome.scripting.executeScript({ world: "MAIN" })`으로 페이지 컨텍스트에
들어갑니다.

## POVIS 지도면담입력 화면 구조 (2026-09-09 교수 계정 실측)

`povis.js`의 `povisStep` 주석에도 있습니다. URL `/zu4a/zuiep_1000`, iframe 없음,
JSONModel 하나.

| 화면 | 무엇 | 경로 / 찾는 법 |
|---|---|---|
| 목록 | 학생 테이블 | `sap.m.Table`, items → `/GT_HD`, 행 `{STDID, ST_NAME, ZSTAT_CDT, …}` |
| 목록 | 학번 링크 | 행의 `sap.m.Link`, `firePress()` → `/GS_ST_INFO` = `{STDID, ST_NAME}`, `/GT_LIST`(면담내역 `{ZCON_DATE, ZITV_GB_T, P_OBJID_T}`) 로드 |
| 목록 | 진입 버튼 | 텍스트 `지도면담 입력` (`EV_GUIDE_ITV_INPUT`) |
| 입력 | 면담일 | `/GS_DT_LIST/ZCON_DATE`, `"YYYYMMDD"`, 학기 범위 제한 있음 |
| 입력 | 학업지도 | `/GS_DT_LIST/ZITV_01_S` |
| 입력 | 생활지도 | `/GS_DT_LIST/ZITV_02_S` |
| 입력 | 진로지도 | `/GS_DT_LIST/ZITV_03_S` |
| 입력 | 기타사항 | `/GS_DT_LIST/ZITV_04_S` |
| 입력 | 버튼 | `저장`(`EV_SAVE_CREATE`), `이전`(`EV_BACK`) — 값을 채운 채 `이전`을 눌러도 확인창 없음 |
| 저장 후 | 성공 | 토스트 `저장되었습니다` → 목록으로 자동 복귀, `/GT_LIST` +1 |
| 저장 후 | 실패 | 토스트만 뜨고 화면 유지 (예: `면담결과를 입력하세요.` = 값이 서버에 안 실림) |

DOM id(`__table3`, `__button32`)는 로드마다 바뀌므로 쓰지 않습니다.

## 주의

- `/GS_DT_LIST`는 구조체 하나를 학생 사이에 재사용합니다. 그래서 네 항목을
  매번 전부(빈 값 포함) 씁니다 - 안 그러면 앞 학생의 기타사항이 다음 학생
  화면에 남아 있다가 함께 저장됩니다.
- 저장이 확인창 없이 바로 일어나므로, 처음 쓸 때는 "채우기만 하고 저장하지
  않기"로 한 번 돌려 보는 것을 권합니다.
- **인증** — Commeet 세션 쿠키가 `SameSite=Lax`라, 확장에서 보낸 요청에
  쿠키가 실리는지는 크롬 동작에 달려 있습니다. 로그인은 성공했는데 이후
  호출이 401로 돌아온다면 이 문제입니다. `docs/povis-extension-handoff.md` 참고.
