# Commeet → POVIS 자동입력 (데모)

POVIS 입력 화면에 Commeet 면담 기록을 자동으로 채울 수 있는지 확인하기 위한
**타당성 검증용 데모**입니다. 아직 Commeet 서버에 붙지 않고, 팝업에 하드코딩된
가짜 면담 기록을 씁니다.

## 설치

1. Chrome에서 `chrome://extensions` 열기
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → 이 `extension/` 폴더 선택
4. POVIS 탭으로 가서 툴바의 확장 아이콘 클릭

권한은 `https://povis.postech.ac.kr/*` 하나뿐입니다. 다른 사이트에서는 아무것도
하지 않습니다.

## 쓰는 법

- **현재 화면 필드 스캔** — 지금 화면의 입력 필드와 그 *바인딩 경로*를 뽑습니다.
  나중에 교수 계정으로 **지도면담입력** 화면을 열고 이걸 돌리면, Commeet의
  네 갈래(학업/생활/진로/기타)를 어느 경로에 넣어야 하는지 알 수 있습니다.
  값은 가져오지 않고 글자 수만 봅니다.
- **데모 데이터로 채우기** — 가짜 면담 기록을 화면에 채웁니다.
- **원래대로 되돌리기** — 채우기 전 값으로 복구합니다.

**저장은 하지 않습니다.** 이 확장은 화면의 값만 바꾸고, 서버 반영은 POVIS의
저장 버튼을 직접 누를 때만 일어납니다. 되돌리기를 하거나 그냥 새로고침하면
원래 상태로 돌아갑니다.

## 왜 이렇게 만들었나

POVIS는 SAPUI5(1.120.21) 앱입니다. 두 가지가 구현을 결정했습니다.

**1. 모델에 써야 한다.** `field.value = ...` 후 `input`/`change` 이벤트를 흉내
내는 흔한 자동입력 방식은 여기서 **조용히 실패합니다**. 화면에는 새 값이
보이지만 UI5 모델은 옛 값 그대로라, 그 상태로 저장하면 옛 값이 전송됩니다.
실측 결과:

| 방법 | 화면 | UI5 모델 |
|---|---|---|
| DOM 직접 쓰기 + 이벤트 | 새 값 | **옛 값** |
| `model.setProperty(path, v)` | 새 값 | 새 값 |

**2. 필드는 바인딩 경로로 찾아야 한다.** UI5가 붙이는 DOM id(`__area57-inner`)는
로드마다 바뀝니다. 대신 `/GS_GOAL/ZGOAL` 같은 바인딩 경로는 백엔드 필드명이라
안정적입니다.

그리고 콘텐츠 스크립트의 격리된 world에서는 `window.sap`이 보이지 않으므로,
`chrome.scripting.executeScript({ world: "MAIN" })`으로 페이지 컨텍스트에
들어갑니다.

## 확인된 것 / 아직 모르는 것

확인: 미래설계 화면(`/zu4a/zuiep_1000`)은 iframe 없는 최상위 문서, CSP 없음,
입력은 전부 평범한 `sap.m.TextArea`, 바인딩 경로로 유일하게 조회됨.

미확인: **정작 목표인 지도면담입력 화면은 교수 계정이 없어 못 봤습니다.** 같은
POVIS/UI5 셸이라 위 결론은 그대로 갈 가능성이 높지만, 필드 경로와 화면 구성은
그 화면에서 "필드 스캔"을 돌려 봐야 합니다. 일부 POVIS 화면이 iframe으로 박혀
있을 가능성도 배제하지 못했습니다.
